# 家庭是独立实体，微信群仅作分享渠道

微信官方文档建议开发者以「群 ID（openGId）」作为群相关功能的标识，前期调研也倾向「群 ID = 家庭 ID」的省事方案，但该方案有硬伤：openGId 只能通过「从群聊分享卡片点入」获得，shareTicket 仅当次小程序生命周期有效，即每个成员必须至少从群卡片进入一次，从小程序「最近使用」直接打开的用户无法归属家庭。因此家庭被建模为独立聚合实体，成员通过家族内生成的邀请链接/卡片加入，微信群只作为邀请的传播渠道，二者无绑定关系。

代价是立家者转让所有权、解散、邀请有效期（7 天）等成员生命周期逻辑需自建，且分享合规（运营规范 5.1.8 组队组团 ≤5 人）依然约束家庭人数上限——这些成本被接受，换取领域模型的干净与入伙体验的确定性。

## Considered Options

- **群 ID = 家庭 ID**：零邀请逻辑，微信替我们管理成员关系。被否决，因为入伙依赖「必须从群卡片进入」的脆弱链路，且家庭 ≠ 微信群（如老人可能不在同一群）。
