# 数据保守主义：解散即冻结不删除，备餐清单精确去重不做换算与模糊合并

两项决策共享同一个理由：家庭厨房是小数据、高信任、低风险场景，宁保守勿激进。其一，解散家庭 = 停用冻结，家庭及全部点餐/备餐记录保留在库中但不可访问、不可再加入、成员关系解除，物理删除不做——误触解散不致不可逆损失，也无需级联删除逻辑。其二，备餐清单按食材名**精确去重**合并（同名同串才合并），不做计量单位换算（半斤 + 半斤 = 1 斤由用户自录时自理）、不做同义词模糊合并（「西红柿/番茄」会分成两行）——依赖家庭成员录入命名一致，而非系统替用户做语义猜谜。

## Consequences

- 存储只增不减：数据不删，膨胀上限由家庭数与 5 人成员上限自然约束，可接受。
- 备餐清单的合并质量取决于录入纪律，这是明确接受的协作成本。
